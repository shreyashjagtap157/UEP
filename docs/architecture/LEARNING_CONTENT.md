# Learning Content Architecture — 0.5.0.0

Learning content is split into a provider-independent content domain and a storage adapter boundary. Academic records store stable resource/version metadata; provider-specific locators never leak into academic rules.

## Upload pipeline

`initiate -> chunk/offset -> resume -> SHA-256 verify -> provider stream -> storage object -> resource version`

Chunks are appended to disk-backed staging files and final provider writes consume streams. Large files are never intentionally loaded wholly into JVM heap. The API uses explicit offsets so interrupted uploads can resume safely and rejects overlapping/out-of-order chunks.

## Providers

- Local filesystem: compact/on-prem development and small deployments.
- S3-compatible: AWS SDK v2 with endpoint override/path-style support for S3, MinIO and compatible object stores.
- Google Drive / Shared Drive: Drive v3 REST adapter, selected by configured Shared Drive identity.

Provider credentials remain deployment secrets. Resource records contain only provider-neutral storage-object references.

## Resource model

A learning resource has a stable key and immutable numbered versions. Each version contains exactly one textual body or one storage object. Visibility, release/expiry window and download policy are evaluated server-side. Historical versions are retained according to tenant retention policy.

## Security invariants

- tenant IDs participate in storage/resource foreign keys;
- upload offsets are monotonic;
- finalization requires exact byte count and optional SHA-256 match;
- object paths are generated by the server;
- local storage prevents path traversal;
- download authorization is checked before opening provider streams;
- provider credentials never appear in resource API responses.

Malware scanning is represented explicitly by scan state. An optional ClamAV INSTREAM adapter scans the staged file before provider finalization. Until a scanner is configured, objects are marked `NOT_CONFIGURED` rather than falsely claiming they were scanned; detected malware is rejected and never finalized into provider storage.
